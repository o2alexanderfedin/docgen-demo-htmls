This document outlines the past, current, and planned release schedule for the LLM Gateway, providing visibility into the product's evolution and future direction.

## Current Status

The LLM Gateway is currently in **General Availability (v1.5)**, with a stable production-ready release that includes all core functionality:

- Multi-provider LLM access
- Comprehensive prompt management
- Security and governance features
- Basic observability and analytics
- Performance optimization capabilities
- Developer experience tools

The product has been deployed in production environments across multiple industries, with particular adoption in financial services, healthcare, technology, and professional services sectors.

## Release Strategy

The LLM Gateway follows a structured release methodology:

### Release Types

- **Major Releases** (x.0): Significant new functionality, potential architectural changes
- **Minor Releases** (1.x): New features and enhancements with backward compatibility
- **Patch Releases** (1.5.x): Bug fixes, security updates, minor improvements

### Release Cadence

- **Major Releases**: Every 12-18 months
- **Minor Releases**: Every 3-4 months
- **Patch Releases**: As needed, typically every 2-4 weeks
- **Security Fixes**: Expedited as needed

### Release Process

1. **Alpha**: Internal testing of new features
2. **Beta**: Limited external testing with key customers
3. **Release Candidate**: Final validation before release
4. **General Availability**: Full production release
5. **Long-Term Support**: Extended support for specific versions

## Feature Request Process

We welcome input on our product roadmap and feature priorities. To submit feature requests:

1. **Enterprise Customers**: Contact your account representative or submit through the customer portal
2. **Community Users**: Submit requests through the community forum or GitHub issues
3. **Partners**: Engage through the partner portal or contact the partner management team

Feature requests are evaluated based on:
- Strategic alignment
- Customer demand
- Technical feasibility
- Resource requirements
- Compatibility with product vision

High-priority requests may be incorporated into upcoming releases, while others may be scheduled for future consideration based on overall roadmap alignment.
